# I2CP-Client E2E-Test 2026-08-07

Manuelles Test-Skript für den I2CP-Client-Android-Workflow mit `net.i2p.android`
als externem I2P-Router (siehe Plan `2026-08-07-i2cp-client-android.md`, §2.1
Prozess-Topologie: SecuChat-APK ↔ `:i2p`-Prozess via I2CP-Plugin, kein Embedded
Router in v0.1).

## Voraussetzungen

Hardware / Setup:
- A50 (Seriennummer `R58M80LEXMK`) und A54 (Seriennummer `RZCW60ZZDJH`).
  > Hinweis: Seriennummern vor dem Test mit `adb devices` verifizieren —
  > Geräte-IDs können sich bei Werks-Reset ändern.
- Beide Geräte haben `net.i2p.android` aus dem Play Store installiert.
- Beide Geräte: in der I2P-App → **Einstellungen** → **I2CP-Benutzeroberfläche**
  → **Tunnel-Freigabe aktivieren** (startet den I2CP-Server auf `127.0.0.1:7656`).
- Beide Geräte: **5–10 Min warten**, bis der I2P-Router bereit ist (NetDB-Build,
  LeaseSet-Publikation). In der I2P-App zeigt der Status „Netzwerk: OK" an.

Build:
- Frisch gebautes Debug-APK: `app/android/app/build/outputs/apk/debug/app-debug.apk`
  (`cd app/android && ./gradlew assembleDebug`).

Test-Treiber (CDP):
- Chrome / Chromium auf dem Entwickler-Laptop (für `chrome://inspect`).
- `adb` im `PATH`.

## CDP-Debug-Brücke

SecuChat exponiert im Browser-/WebView-Kontext eine Debug-Brücke unter
`window.__i2pDebug` (siehe `app/src/services/i2p.ts:736`). Diese wird in
Development-Builds automatisch gesetzt und ist die Schnittstelle für
CDP-getriebene E2E-Tests:

```ts
// app/src/services/i2p.ts:733-737
export const i2pService = new I2PService();
// DEV/TEST: global exposure for CDP-driven E2E tests
if (typeof window !== 'undefined') {
  (window as unknown as { __i2pDebug?: unknown }).__i2pDebug = i2pService;
}
```

Relevante Methoden (Stand 2026-08-07):

| Methode | Signatur | Zweck |
|---|---|---|
| `getStatus()` | `() => I2PStatus` (Zeile 326) | Liefert `{ samConnected, samAvailable, address, leasesetPublished, ... }`. Hinweis: `samConnected` ist ein Legacy-Feldname — auf Android ist es tatsächlich der Status der `i2pPlugin`-Verbindung, nicht der rohen SAM-Socket. |
| `connectToPeer(b32, publicKey?, opts?)` | `(b32: string, publicKey?: Uint8Array, opts?: { maxRetries?: number }) => Promise<I2PPeer>` (Zeile 353) | Stellt eine SAM-STREAM-CONNECT-Verbindung her. Liefert ein `I2PPeer`-Objekt (nicht nur eine `streamId`). Dedupiziert parallele Calls für dieselbe b32. |

## Schritte

Pro Gerät (A50 und A54 identisch) — am Beispiel A50:

1. **APK installieren**
   ```bash
   adb -s R58M80LEXMK install -r app/android/app/build/outputs/apk/debug/app-debug.apk
   ```

2. **App öffnen und Onboarding prüfen**
   ```bash
   adb -s R58M80LEXMK shell am start -n com.secuchat.app/.MainActivity
   ```
   Erwartung: Onboarding zeigt das Block-Modal („I2CP-Freigabe fehlt"), weil die
   I2P-App zwar installiert ist, aber die Tunnel-Freigabe noch nicht aktiviert
   wurde. (Falls die Freigabe bereits aktiv ist, erscheint das Modal nicht —
   dann zu Schritt 4 springen.)

3. **I2P-App: Tunnel-Freigabe aktivieren**
   - I2P-App öffnen
   - Einstellungen → I2CP-Benutzeroberfläche → Tunnel-Freigabe aktivieren
   - 5–10 Min warten, bis Router bereit

4. **Erneut prüfen**
   - Zurück zu SecuChat
   - Im Block-Modal auf **„Erneut prüfen"** tippen
   - Erwartung: Modal verschwindet

5. **CDP-Pipeline starten**
   ```bash
   # WebView-DevTools-Socket der App finden
   SOCK=$(adb -s R58M80LEXMK shell "cat /proc/net/unix | grep -oE 'webview_devtools_remote_[0-9]+' | head -1")
   # Auf lokalen TCP-Port forwarden
   adb -s R58M80LEXMK forward tcp:9221 localabstract:$SOCK
   ```

6. **Browser: chrome://inspect**
   - `chrome://inspect` im Chrome auf dem Laptop öffnen
   - SecuChat-WebView erscheint in der Liste → **inspect** klicken
   - DevTools-Console öffnen

7. **Status prüfen**
   ```js
   window.__i2pDebug.getStatus()
   // Erwartung:
   // { samConnected: true, samAvailable: true, address: '<eigene-b32>', leasesetPublished: true, ... }
   ```

8. **Gegenstelle verbinden**
   ```js
   // b32 des A54 aus dessen window.__i2pDebug.getStatus().address holen
   await window.__i2pDebug.connectToPeer('<A54-b32>')
   // Erwartung: Promise resolved mit I2PPeer-Objekt in < 60s
   ```

9. **Chat A50 → A54**
   - In SecuChat auf A50: Kontakt „A54" öffnen → Nachricht senden
   - Erwartung: A54 zeigt die Nachricht in < 5s an

10. **Chat A54 → A50**
    - Identisch in Gegenrichtung (Schritte 5–9 auf A54 wiederholen, b32 von A50 verwenden)
    - Erwartung: A50 zeigt die Nachricht in < 5s an

## Pass-Kriterien

| Schritt | Kriterium |
|---|---|
| 2 | Block-Modal „I2CP-Freigabe fehlt" wird angezeigt |
| 4 | Modal verschwindet nach „Erneut prüfen" |
| 7 | `getStatus().samConnected === true` und `address` ist eine gültige 52-Zeichen-b32 |
| 8 | `connectToPeer()` resolved in **< 60 s** mit einem `I2PPeer`-Objekt |
| 9 | Nachricht erscheint auf Empfänger in **< 5 s** |
| 10 | dito in Gegenrichtung |

## Fehleranalyse (Logcat)

Bei Fehlern in Schritt 7–10:

```bash
adb -s R58M80LEXMK logcat | grep -iE 'I2CP|SecuChat|I2P'
```

Der Logcat-Tag des nativen Plugins ist `SecuChat:I2CP`
(`app/android/app/src/main/java/com/secuchat/app/plugin/I2PPlugin/I2PPlugin.java:17`).
Der `grep`-Filter matcht `I2CP`, `SecuChat` und generische `I2P`-Einträge in
einem Schritt.

Typische Fehlerbilder:
- `Cannot connect - SAM not connected` (i2p.ts) → I2P-App-Freigabe prüfen, oder
  I2P-Router noch nicht bereit (NetDB-Build).
- `STREAM STATUS RESULT=INVALID_ID` → Known Limitation siehe unten.

## Known limitations / Out of scope (v0.1)

- **Session-Recovery (Spec §4.3)** ist in v0.1 **nicht** implementiert. Wenn
  der I2P-Tunnel stirbt (Router-Crash, Netzwechsel, DoS-Schutz von i2pd),
  versucht SecuChat **nicht**, die SAM-Session automatisch wiederherzustellen.
  Workaround für v0.1: **App neu starten**. Folgeticket ist im Plan
  `2026-08-07-i2cp-client-android.md` §4.3 für v0.3 vorgemerkt
  (Reconnect-Loop in `I2CPSocketManager`).
- **Bidirektionaler STREAM-CONNECT** setzt voraus, dass beide Geräte ihren
  LeaseSet publiziert haben (`getStatus().leasesetPublished === true`). Ohne
  publizierten LeaseSet ist der Peer unsichtbar in der DHT — `connectToPeer`
  hängt dann bis zum 60-s-Timeout.
